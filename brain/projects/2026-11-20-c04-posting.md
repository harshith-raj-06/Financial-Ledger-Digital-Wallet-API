# C04 posting on the migrated ledger

The posting branch incorporates the H02 runner and migrations from main at
`5d0858e`. The test database uses the same migration entry point as the CLI.
The tests cover transaction visibility from a second connection, exact reversal
entries, conditional debits, integer overflow and rollback after a failed write.
HTTP tests use a test-only route to verify the public error envelope after
rollback. [Posting decision](../../docs/adr/0001-posting-transaction-ownership.md)
and [C04 tests](../../tests/test_posting.py).

Local verification passed all 241 Python tests, including 52 posting cases.
Ruff and the package build passed. Prism served the fixtures for all 11
operations and the documented validation error.

In a separate service-level run, 50 connections each attempted to send 3,000
minor units from a wallet holding 100,000. With a 5,000 ms busy timeout and
one attempt per writer, 33 committed and 17 returned `INSUFFICIENT_FUNDS`.
The sender retained 1,000 and the receiver held 99,000. The initial deposit
and 33 transfers produced 68 entries. SQLite's integrity check returned `ok`.

H03 integration and two human approvals remain open on [draft PR #19](https://github.com/harshith-raj-06/Financial-Ledger-Digital-Wallet-API/pull/19). Repeat the concurrency
case over HTTP once the transfer endpoint is available. [Issue #16](https://github.com/harshith-raj-06/Financial-Ledger-Digital-Wallet-API/issues/16).
